# Fix BUG-002 — persist edited due dates

## Feature Overview and Goal

**Intent**: Close BUG-002 — a due date set in the edit dialog is lost after save. The update handler must read the submitted due-date field and persist it on the todo, and the edit dialog must pre-fill the current value.

## Acceptance Scenarios

- [x] Editing a todo, setting a due date, and saving persists the due date so it is still present after the list re-renders.
- [x] The edit dialog pre-populates the existing due date when reopened.

## Implementation Plan

- [x] In src/app/routes/todos.py, read the due-date form field in the update handler and store it on the todo.
- [x] In src/app/templates/app.html, bind the edit dialog's due-date input to the todo's current value.

## Implementation Observations

### Run: 2026-08-28

- Legacy FIS provenance was recovered from the filename and sibling `plan.json`.
- The edit dialog already passes the todo's formatted due date through `data-todo-due-date` to `openEditTodoDialog`; no template change was required.
- The full suite has one unrelated BUG-003 baseline failure: quick-add todos still have no default priority.
