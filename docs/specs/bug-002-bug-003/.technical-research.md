## Shared Architectural Decisions

1. Preserve the HTMX-first contract.
   - Both fixes must continue returning existing HTML partials or the standard error partial.
   - No JSON endpoint, client-only state fix, or alternate edit flow is in scope.

2. Treat Due Date as a date-only value in this UI path.
   - The edit control is `type="date"` and `format_date_input()` emits `YYYY-MM-DD`.
   - The server-side fix should accept that date-only payload and persist a value that round-trips back through `format_date_input()` without client-side conversion.

3. Malformed due-date submissions must fail explicitly in the existing HTML error pattern.
   - Silent fallthrough is the defect called out by the PRD.
   - Success responses must be reserved for payloads that actually persisted the intended date or intentionally cleared it.

4. Quick-add must set an explicit default Priority at creation time.
   - Relying on UI defaults or later edit normalization is insufficient because quick-add persists immediately.
   - The stored value must be one of the supported priority literals used elsewhere in the app: `low`, `medium`, `high`.

5. Keep execution waves sequential despite product independence.
   - The PRD asks for independent thin stories, but the current codebase concentrates both fixes in the same route and test modules.
   - Separate waves reduce merge churn while preserving independent acceptance, FIS ownership, and backlog traceability.
