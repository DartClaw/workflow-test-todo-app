## Shared Architectural Decisions

1. **Keep the fix inside existing HTML-partial contracts**
   - Rationale: project rules are HTMX-first. Both stories must keep returning `TemplateResponse(...)` fragments and keep `partials/error.html` for user-visible failures.

2. **Treat the edit dialog as the source of the due-date input contract**
   - Rationale: the UI uses `type="date"` in `src/app/templates/app.html:139`, and the row partial uses `format_date_input(todo.due_date)` when reopening. The route should accept the dialog's actual format rather than expecting a different datetime-local payload.

3. **Keep quick-add defaulting at the route layer, not as a broader data-model policy**
   - Rationale: the PRD scopes the default-priority change to quick add only. Setting the default in `create_todo` preserves explicit priority choices from the edit flow and avoids incidental behavior changes in other creation paths.

4. **Use route tests as the primary proof surface**
   - Rationale: both defects are request/response regressions on authenticated todo routes. Strengthening `tests/test_todos.py` gives the narrowest durable proof without forcing browser-only validation for every scenario.
