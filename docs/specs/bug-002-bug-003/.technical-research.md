## Project Context

- Stack is Python 3.11+ with FastAPI, Jinja2, SQLAlchemy 2, SQLite, HTMX, Shoelace, SortableJS, `uv`, and `pytest`/`httpx`. Runtime behavior is server-rendered HTML partials rather than JSON APIs or SPA state sync.
- App shape is small and conventional: `main.py` wires lifespan, DB init, demo seed data, routers, static mount, and global 401 / SQLAlchemy handlers; `database.py` defines `User`, `TodoList`, and `Todo`; `core/deps.py` owns simple session auth; `routes/` splits pages, auth, lists, and todos; `templates/partials/` holds fragment responses.
- Ordering is explicit via `position` on lists and todos, with insertions using `max(position) + 1` and reordering mutating adjacent rows rather than rebuilding collections.
- HTMX-first is the core architectural rule. Route handlers return `TemplateResponse` partials or bare `Response` objects with HTMX headers. Errors are HTML-fragment based via `partials/error.html`; route-level validation is ad hoc in handlers, not enforced through the Pydantic models in `src/app/models/`.
- OOB swaps are an established idiom. `partials/todo_item_with_oob.html` returns a todo row plus an out-of-band sidebar count update; create-path work must preserve that response shape.
- Template helpers (`is_overdue`, `is_due_today`, `format_date`, `format_date_input`) are registered separately in each router with its own `Jinja2Templates` instance.
- Auth is intentionally simplistic and must remain unchanged for this effort: module-level in-memory `sessions`, 1-hour expiry, plain-text passwords, cookie-based `session_id`.
- Ownership checks are first-class patterns. Todo routes fetch the resource and verify parent-list ownership via `_verify_list_access()` before rendering success or error partials.
- Tests use in-memory SQLite with `StaticPool`, dependency overrides for `get_db`, and explicit `sessions` cleanup in `tests/conftest.py`. Route tests assert HTML fragments, headers, and DB side effects rather than JSON contracts.

## Shared Architectural Decisions

### Shared decisions and conventions

1. The shared seam between `BUG-002` and `BUG-003` is the todo row plus edit-dialog contract, not the database model. The create path returns `partials/todo_item_with_oob.html`; the update path returns `partials/todo_item.html`; both rely on row dataset attributes to hydrate later edits.
2. The canonical due-date wire format for this scope is `YYYY-MM-DD`, because the dialog uses `<sl-input type="date">` and the row dataset is produced with `format_date_input(todo.due_date)`. The spec for `BUG-002` should preserve naive date storage while fixing the parser mismatch.
3. The canonical Priority domain is `low | medium | high`. The spec for `BUG-003` should make create-time defaulting authoritative rather than relying on UI defaults or later edits.
4. Validation and business-rule failures in create/update flows should return `templates.TemplateResponse(..., name="partials/error.html", context={"error": ...})`, usually without redirect. Unauthenticated access remains the global 401 / `HX-Redirect` path and is out of scope.
5. Keep naming aligned with the existing codebase: verb-first route functions, underscore-prefixed narrow helpers, partial names that describe UI fragments, and short plain-text validation messages.
