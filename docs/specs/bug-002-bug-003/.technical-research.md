## Project Context

- Stack: FastAPI routes return HTML fragments via `Jinja2Templates`; HTMX swaps those fragments into the page. Todo CRUD lives in `src/app/routes/todos.py`, ORM models live in `src/app/database.py`, template helpers live in `src/app/utils.py`, and the edit dialog markup lives in `src/app/templates/app.html`.
- Existing todo rendering contract: the edit dialog uses `<sl-input ... type="date">` in `src/app/templates/app.html:139`, while each rendered row exposes `data-todo-due-date="{{ format_date_input(todo.due_date) }}"` and `data-todo-priority="{{ todo.priority }}"` in `src/app/templates/partials/todo_item.html:1-7`.
- Current defect signatures:
  - `BUG-002`: `update_todo` in `src/app/routes/todos.py:153-224` parses `due_date` using `datetime.strptime(due_date, "%Y-%m-%dT%H:%M")`, but the UI and tests submit `YYYY-MM-DD`. The handler then swallows `ValueError`, causing a silent no-op for invalid formats while still returning the success fragment.
  - `BUG-003`: `create_todo` in `src/app/routes/todos.py:67-121` instantiates `Todo(...)` without `priority`, and `Todo.priority` in `src/app/database.py:72-83` has no default. The tests already expect `low`, so the current behavior contradicts the test contract and PRD.
- Test harness: `tests/conftest.py` builds a fresh in-memory SQLite DB per test with `StaticPool` and provides `authenticated_client`, `test_list`, and `test_todo`. The existing regression surface is concentrated in `tests/test_todos.py`.
- Workflow guidance relevant to execution:
  - HTMX-first: keep fragment responses, do not introduce JSON APIs.
  - Auth is intentionally simple and out of scope.
  - Use canonical terms `Todo`, `TodoList`, `Priority`, and `Due Date` from `docs/UBIQUITOUS_LANGUAGE.md`.

## Shared Architectural Decisions

1. **Keep both fixes inside existing server-rendered fragment flows.**
   - Rationale: the PRD explicitly preserves the HTMX + Jinja fragment contract, and neither defect requires a transport-layer change.

2. **Separate merge ownership by boundary, not by feature flag.**
   - S01 owns the todo update path in `src/app/routes/todos.py`.
   - S02 owns the Todo model default in `src/app/database.py`.
   - Both stories treat templates as read-only contracts unless execution discovers a real mismatch.

3. **Model boundary is the preferred source of truth for quick-add Priority defaults.**
   - Rationale: a model default covers quick add and any other future Todo creation path without widening route validation logic. This also keeps `BUG-003` out of the route file used by `BUG-002`.

4. **Invalid due-date submissions must preserve trust, not fake success through mutation.**
   - Rationale: the PRD allows either preserving the old value or surfacing the normal error partial; the simpler fit with the current code path is to leave the stored value unchanged and ensure tests prove that behavior.

5. **Regression coverage should be split by story.**
   - Rationale: the PRD requires merge-safe thin stories with isolated ownership. Dedicated test files are the cleanest way to avoid both stories modifying `tests/test_todos.py`.
