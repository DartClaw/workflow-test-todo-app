# BUG-001 Technical Research

## Source Request

- `BUG-001` from `docs/PRODUCT-BACKLOG.md#known-defects`
- Requested behavior: when a `Todo` is deleted, the sidebar incomplete-count must refresh via the same HTMX OOB pattern already used by toggle completion.

## Codebase Findings

### Relevant Files

- `src/app/routes/todos.py:33-37` defines `_get_list_todo_count(db, list_id)`, the existing helper for sidebar incomplete-count values.
- `src/app/routes/todos.py:243-283` shows the reference implementation in `toggle_todo()`: mutate the `Todo`, recompute count, return `partials/todo_item_with_oob.html`.
- `src/app/routes/todos.py:286-306` is the defective `delete_todo()` path: it verifies ownership, deletes the `Todo`, commits, and returns an empty `200` response with no OOB markup.
- `src/app/templates/partials/todo_item_with_oob.html:1-4` demonstrates the canonical OOB swap structure for count refreshes.
- `src/app/templates/partials/todo_deleted_oob.html:1-2` already exists and renders only the sidebar count OOB fragment for delete flows.
- `src/app/templates/partials/todo_list_item.html:20` defines the target DOM node: `id="list-{{ list.id }}-count"`.
- `tests/test_todos.py:84-92` currently verifies deletion only at the database level.
- `tests/test_integration.py:163-180` already proves the OOB pattern for completion toggles by asserting `hx-swap-oob` in the response body.

### Architecture Fit

- This app is HTMX-first. Server responses own UI state and return HTML fragments, not JSON.
- OOB swaps are the documented pattern whenever one interaction must update multiple DOM regions.
- For deletion, the primary target is the removed todo row and the secondary target is the sidebar count badge. Returning a delete-specific OOB-only partial fits the existing architecture and avoids a wider sidebar rerender.

## Recommended Implementation Shape

1. In `delete_todo()`, capture `list_id` before deleting the `Todo`.
2. Delete and commit the `Todo`.
3. Recompute incomplete count with `_get_list_todo_count(db, list_id)`.
4. Return `partials/todo_deleted_oob.html` with `list_id` and `count`.

## Test Implications

- Add a route-level regression test proving the delete response now includes `hx-swap-oob` and the updated count when deleting an incomplete `Todo`.
- Add coverage for deleting a completed `Todo` so the count remains unchanged while the OOB badge update still renders.
- Preserve existing failure semantics for missing or unauthorized deletes unless implementation uncovers a blocker; BUG-001 does not justify broadening the delete contract.

## Assumptions

- The existing `todo_deleted_oob.html` partial is intentionally staged for this bug and should be reused rather than replaced.
- A standalone OOB response is sufficient for HTMX delete flow because the client-side delete action already removes the row, leaving only the sidebar count as the missing server-driven update.
