# Technical Research

## BUG-001 – Sidebar incomplete-count on todo delete

### Architecture analysis
- `src/app/routes/todos.py:33-37` already centralizes incomplete-count calculation in `_get_list_todo_count()`.
- `src/app/routes/todos.py:125-132` and `src/app/routes/todos.py:276-283` show the established pattern: after a todo mutation affects completion state, the route recomputes the count and returns `partials/todo_item_with_oob.html` with `count` and `list`.
- `src/app/routes/todos.py:286-306` is the outlier for delete. It preserves ownership checks and status codes, but returns a bare `Response(status_code=200)` so HTMX deletes the row without any sidebar OOB update.
- `src/app/static/js/app.js:166-173` sends todo deletes through `htmx.ajax('DELETE', ...)` with `target: #todo-{id}` and `swap: delete`. The response therefore needs only the OOB count fragment; the main target is removed client-side.

### Template and DOM contract
- `src/app/templates/partials/todo_item_with_oob.html:3-4` defines the house OOB swap contract for sidebar count updates: `<span id="list-{{ list.id }}-count" hx-swap-oob="true">{{ count }}</span>`.
- `src/app/templates/partials/todo_deleted_oob.html:1-2` already exists and matches the delete use case: it renders only the sidebar count OOB span keyed by `list_id`.
- `src/app/templates/partials/todo_list_item.html:20` defines the sidebar counter DOM id that all OOB responses must target: `list-{{ list.id }}-count`.

### Behavioral implications
- Deleting an incomplete Todo must decrement the sidebar count immediately in the same HTMX response.
- Deleting a completed Todo must leave the count unchanged because `_get_list_todo_count()` filters on `Todo.is_completed == False`.
- Missing or unauthorized deletes should preserve the current `404` / `403` responses and must not emit misleading sidebar updates.

### Test patterns
- `tests/test_todos.py:84-92` currently proves only that delete removes the row from the database.
- The repo’s fixture stack in `tests/conftest.py:70-113` supports an authenticated client plus a seeded `TodoList` / `Todo`, so the new coverage can stay in `tests/test_todos.py` and assert both HTTP body content and database state.
- The strongest regression test is response-body based: verify the delete response contains `hx-swap-oob="true"` and the correct `list-{id}-count` span for incomplete deletes, and verify completed deletes return the unchanged count.
