# Technical Research - BUG-001 Sidebar Incomplete Count Delete OOB

## Architecture Analysis

- The app is HTMX-first and server-rendered. Successful interactive routes are expected to return HTML partials, not JSON, and multi-region updates use HTMX out-of-band swaps.
- `toggle_todo` is the closest reference implementation for this defect. It recomputes the incomplete count after the database change and returns a composite partial so the todo row and sidebar badge stay in sync in one response.
- `delete_todo` currently diverges from that pattern. The client removes the row via `swap: delete`, but the route returns a bare `200` with no response body, so the sidebar badge cannot update until a full reload.

## Relevant File Map

- `src/app/routes/todos.py:33-37` - `_get_list_todo_count()` helper already computes the sidebar badge value from incomplete `Todo` rows only.
- `src/app/routes/todos.py:243-283` - `toggle_todo()` shows the existing OOB pattern to mirror for successful deletes.
- `src/app/routes/todos.py:286-306` - `delete_todo()` currently deletes the row and returns `Response(status_code=200)` with no OOB markup.
- `src/app/templates/partials/todo_item_with_oob.html:1-4` - composite todo-row + OOB badge update used by toggle and create flows.
- `src/app/templates/partials/todo_deleted_oob.html:1-2` - delete-specific OOB badge fragment already exists but is currently unused.
- `src/app/templates/partials/todo_list_item.html:20` - sidebar badge DOM contract is `id="list-{{ list.id }}-count"`.
- `src/app/static/js/app.js:166-173` - todo delete confirmation uses `htmx.ajax('DELETE', ...)` targeting `#todo-{id}` with `swap: 'delete'`.

## Behavior Gap

- Incomplete todo delete is the only count-mutating todo action that does not return an OOB badge update.
- Completed todo delete still needs the same response path, because the sidebar badge is derived from incomplete todos and must remain correct even when its numeric value does not change.
- Deleting the last incomplete todo is the zero-state boundary for this bug. The badge must render `0` immediately, not disappear until reload.

## Test Surface

- `tests/test_todos.py:84-92` currently proves only that the database row is deleted. It does not assert HTML response shape or sidebar badge updates.
- `tests/test_integration.py:163-179` already locks the toggle path to an OOB response and is the right pattern for a delete regression test.
- `tests/conftest.py:71-113` provides `authenticated_client`, `test_list`, and `test_todo`, which are sufficient to build route and integration tests for incomplete, completed, and rejection-path deletes without new fixtures.

## Execution Notes

- Preferred implementation path: successful `DELETE /api/todos/{todo_id}` should recompute the post-delete incomplete count and return the delete-specific OOB partial while preserving current `403` / `404` behavior.
- If browser validation shows `swap: 'delete'` prevents the OOB fragment from being processed, make the smallest HTMX-compatible adjustment needed to keep row removal and sidebar badge updates in the same interaction. Do not switch to client-side count math or a full sidebar reload.
