# Technical Research

## BUG-001 – Sidebar incomplete-count not updating after Todo delete

### Requirement source

- `docs/PRODUCT-BACKLOG.md:25` defines `BUG-001` as a sidebar incomplete-count defect on Todo delete and explicitly points to the toggle flow as the expected HTMX OOB swap pattern.

### Relevant architecture and conventions

- `AGENTS.md:33-38` states that routes return HTML partials and that OOB swaps are the standard mechanism when one interaction updates multiple DOM regions.
- `AGENTS.md:152-155` requires HTMX-first HTML responses and backlog-scoped bug handling.
- `AGENTS.md:160-163` calls out visual validation for interactions that update multiple DOM regions and specifically mentions checking `hx-swap-oob`.
- `docs/UBIQUITOUS_LANGUAGE.md:24-26` defines `Partial`, `OOB Swap`, and `Error Partial`; use those terms in the FIS and implementation.

### Existing implementation pattern

- `src/app/routes/todos.py:33-37` provides `_get_list_todo_count`, the shared query used by create and toggle flows.
- `src/app/routes/todos.py:125-132` creates a Todo and returns `partials/todo_item_with_oob.html` with both the new row and updated count.
- `src/app/routes/todos.py:276-283` toggles completion and returns the same composite partial with refreshed count.
- `src/app/templates/partials/todo_item_with_oob.html:1-4` includes the row partial plus an OOB `<span id="list-{{ list.id }}-count" hx-swap-oob="true">`.
- `src/app/templates/partials/todo_deleted_oob.html:1-2` already exists as a delete-oriented OOB count partial but is currently unused by the delete route.

### Current defect shape

- `src/app/routes/todos.py:286-306` deletes the Todo and returns a bare `200` response with no HTML body, so HTMX removes the targeted row via `swap: 'delete'` but receives no OOB payload to refresh the sidebar count.
- `src/app/static/js/app.js:166-173` sends `DELETE /api/todos/{id}` with `target: #todo-{id}` and `swap: 'delete'`, which means the success response only needs to carry OOB markup; the row removal is still driven by the client-side swap mode.
- `src/app/templates/partials/todo_list_item.html:20` renders the sidebar badge with id `list-{{ list.id }}-count`, matching the OOB partial target id.

### Test surface

- `tests/conftest.py:13-113` provides an in-memory SQLite setup plus `authenticated_client`, `test_list`, and `test_todo` fixtures suitable for route-level HTML response assertions.
- `tests/test_todos.py:84-92` currently verifies database deletion only.
- No existing test asserts that delete responses include OOB markup or that the updated incomplete count is correct.

### Recommended solution shape

- Keep the current delete interaction model: HTMX still targets the Todo row and swaps with `delete`.
- After authorization and before deletion side effects are finalized, keep enough list context to compute the refreshed incomplete Todo count.
- Return an HTML partial on successful delete containing only the OOB count update. The existing `partials/todo_deleted_oob.html` is the minimal fit unless implementation reveals a need to rename or generalize it.
- Add a focused route test that exercises a list with multiple incomplete Todos, deletes one Todo, then asserts:
  - the response is `200`
  - the response HTML contains `hx-swap-oob="true"`
  - the response targets the active TodoList count id
  - the response count reflects the post-delete incomplete total
  - the Todo is removed from the database

### Out of scope observations

- `AGENTS.md:88-89` says 403/404 paths should return HTML error partials, but `delete_todo` currently returns bare `Response(status_code=404|403)`. That inconsistency predates this bug and is not required to satisfy `BUG-001`.
