# Technical Research

## BUG-001 - Sidebar incomplete count updates on Todo delete

### Source Request
- Backlog source: `docs/PRODUCT-BACKLOG.md#known-defects`
- Requested behavior: deleting a Todo should update the sidebar incomplete-count using the same HTMX out-of-band pattern already used by toggle.

### Repository Shape
- The project is a small FastAPI + HTMX app with Todo routes in `src/app/routes/todos.py`, partial templates in `src/app/templates/partials/`, and browser behavior in `src/app/static/js/app.js`.
- The canonical specs location is `docs/specs/`, but the directory did not exist before this FIS was generated.

### Relevant Existing Patterns
- `src/app/routes/todos.py:33-37` defines `_get_list_todo_count()`, the shared helper that counts incomplete Todos for one `TodoList`.
- `src/app/routes/todos.py:125-131` returns `partials/todo_item_with_oob.html` after create, pairing the primary Todo markup with a sidebar count OOB swap.
- `src/app/routes/todos.py:243-283` does the same after toggle: update persisted state, recompute count, then return HTML containing `hx-swap-oob`.
- `src/app/templates/partials/todo_item_with_oob.html:1-4` is the composite "row plus count" pattern.
- `src/app/templates/partials/todo_deleted_oob.html:1-2` already exists and contains the exact sidebar-count OOB fragment needed for delete, but it is not currently returned by the route.
- `src/app/templates/partials/todo_list_item.html:20` shows the sidebar badge DOM contract: `id="list-{{ list.id }}-count"`.
- `src/app/static/js/app.js:170-173` sends Todo deletes via `htmx.ajax('DELETE', ...)` with `target: #todo-{id}` and `swap: 'delete'`. Any server-side fix must preserve that client contract.

### Current Bug Shape
- `src/app/routes/todos.py:286-306` deletes the Todo and returns an empty `200` response.
- Because the delete response body is empty, HTMX removes the Todo row but has no OOB markup to update the sidebar count.
- The existing delete-specific partial strongly suggests the intended repair is server-side and already aligned with the codebase's HTMX-first pattern.

### Test Baseline
- `tests/test_todos.py:84-92` only proves that delete removes the database row; it does not assert response content or count behavior.
- `tests/test_integration.py:164-179` already proves the toggle flow returns an OOB fragment for count updates.
- Additional delete coverage should prove:
  - incomplete Todo delete decrements the sidebar count,
  - completed Todo delete leaves the sidebar count unchanged,
  - deleting the last incomplete Todo returns count `0`,
  - 403/404 delete failures do not emit misleading OOB count fragments.

### Architecture Choice
- Preferred approach: keep the existing client-side delete flow and make the successful delete response return the existing delete-specific OOB partial with the recomputed count.
- Rejected alternatives:
  - Re-render the full sidebar: heavier than needed and inconsistent with the narrow OOB pattern already used by create/toggle.
  - Update the count in JavaScript without a server-rendered fragment: pushes UI state logic into the client and breaks the established server-rendered source-of-truth pattern.
  - Return JSON and patch the DOM manually: explicitly contradicts the repository's HTMX-first rules.

### Scope Assumptions
- The defect scope is limited to successful Todo deletes. Existing `403` and `404` delete responses remain status-only unless a later requirement broadens the scope.
- No schema changes, auth changes, or delete-dialog UX changes are required.
