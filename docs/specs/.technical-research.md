# Technical Research

## BUG-001 – Sidebar count updates on todo delete

### Requirement trace

- `docs/PRODUCT-BACKLOG.md#known-defects` defines `BUG-001` as a stale sidebar incomplete-count after todo deletion and explicitly points to the existing HTMX OOB swap pattern used by completion toggles.
- `docs/ROADMAP.md#phase-2-defect-triage` makes backlog defect stabilization the active project phase, so this spec should stay narrowly focused on the reported regression.

### Relevant code map

- `src/app/routes/todos.py:33-37` – `_get_list_todo_count()` is the existing server-side source of truth for sidebar counts and excludes completed todos.
- `src/app/routes/todos.py:125-132` – `create_todo()` already recomputes the count and returns `partials/todo_item_with_oob.html`.
- `src/app/routes/todos.py:243-283` – `toggle_todo()` is the closest success-path reference: mutate state, commit, recompute count, render an HTML partial with `hx-swap-oob`.
- `src/app/routes/todos.py:286-306` – `delete_todo()` verifies ownership, deletes the row, commits, then returns a bare `Response(status_code=200)`. This is the defect location.
- `src/app/templates/partials/todo_item_with_oob.html:1-4` – existing composite OOB response for create/toggle.
- `src/app/templates/partials/todo_deleted_oob.html:1-2` – dedicated delete OOB partial already exists and targets the same sidebar count span.
- `src/app/templates/partials/todo_list_item.html:20` – sidebar badge contract is `id="list-{{ list.id }}-count"`.
- `src/app/static/js/app.js:163-173` – successful deletes use `htmx.ajax('DELETE', ...)` with `target: #todo-{id}` and `swap: 'delete'`, so HTMX can delete the row and still apply OOB updates from the response body.

### Current behavior and implications

- The sidebar count is already server-derived. A client-side decrement would be wrong for completed-todo deletes because completed todos are excluded from `_get_list_todo_count()`.
- The presence of `partials/todo_deleted_oob.html` indicates the intended delete contract was already designed as a server-rendered OOB update; the bug is that the route never returns it.
- Because `delete_todo()` commits before returning, the post-delete count can be recomputed immediately from the database without additional refresh steps.

### Test seams

- `tests/test_todos.py:84-92` currently proves only that the database row is removed. It does not assert response-body content or sidebar count semantics.
- `tests/test_integration.py:163-179` already proves the toggle path emits `hx-swap-oob`; this is the regression pattern to mirror for delete.
- `tests/conftest.py:71-77` provides `authenticated_client`, which is the right fixture for successful delete tests. `tests/conftest.py:98-113` defines `test_todo` as incomplete by default, which is useful for the happy path.

### Assumption chosen in AUTO_MODE

- Preserve the current 403/404 delete behavior as bare `Response` objects. The backlog scope is the successful delete count refresh, and broadening error rendering would add scope that is not required to resolve `BUG-001`.
