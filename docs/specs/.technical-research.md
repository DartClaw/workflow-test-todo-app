# Technical Research - BUG-001 Sidebar Incomplete Count on Todo Delete

Date: 2026-05-03

## Scope

Backlog source:
- `docs/PRODUCT-BACKLOG.md:25` defines `BUG-001` as a sidebar incomplete-count bug specific to deleting a `Todo`, with the expected fix shape called out explicitly: use an HTMX OOB Swap on the delete response.

No external documentation lookup was needed. The existing codebase already contains the relevant HTMX pattern and even a delete-specific partial for the sidebar badge update.

## Current Behavior Analysis

### Why toggle works

`toggle_todo()`:
1. Verifies ownership through the parent `TodoList`.
2. Mutates completion state.
3. Recomputes the incomplete count with `_get_list_todo_count()`.
4. Returns `partials/todo_item_with_oob.html`, which contains the updated row plus `<span ... hx-swap-oob="true">`.

This matches the architecture rule in `CLAUDE.md:33-38`: routes return HTML fragments, and OOB Swaps are the standard way to update multiple DOM regions in one HTMX response.

### Why delete is stale

`delete_todo()`:
1. Verifies the `Todo` exists.
2. Verifies ownership through `_verify_list_access()`.
3. Deletes the `Todo`.
4. Returns `Response(status_code=200)` with no HTML body.

The client still removes the row because the delete dialog uses `swap: 'delete'`, but there is no OOB fragment in the response body to refresh `#list-{id}-count`.

## Chosen Solution Shape

Use the existing delete-specific OOB partial for the delete route instead of changing the client-side delete contract.

Rationale:
- It is the smallest change that fits the repository's HTMX-first architecture.
- It reuses existing artifacts instead of inventing a new partial or JavaScript flow.
- It preserves `swap: 'delete'` for the primary target while allowing the response body to carry the sidebar badge update.
- It keeps the fix surgical to `BUG-001` instead of refactoring unrelated delete behavior.

## Behavioral Decisions Captured for the FIS

- Deleting an incomplete `Todo` must decrement the sidebar badge immediately.
- Deleting a completed `Todo` must leave the badge unchanged, but the response should still carry the authoritative count via OOB so the badge reflects server truth.
- Deleting the final incomplete `Todo` in a `TodoList` must render `0`, not a stale positive value or an empty badge.
- Unauthorized or missing-`Todo` delete behavior stays unchanged for this defect; the FIS should preserve current response codes.

## Test Strategy Notes

Recommended proof paths:
- Extend route-level delete coverage to assert the response contains `hx-swap-oob` and the expected count value.
- Add or extend integration coverage to mirror the existing toggle-count test, but for the delete path.
- Cover both count-changing and count-preserving cases:
  - deleting an incomplete `Todo`
  - deleting a completed `Todo`
  - deleting the last incomplete `Todo` in a `TodoList`

## NOTICED BUT NOT TOUCHING

- `delete_todo()` and `delete_list()` currently return bare `Response` objects for `403`/`404` cases instead of the HTML error-partial pattern described elsewhere in the project guidance. This spec keeps current delete-route failure semantics unchanged because that inconsistency is broader than `BUG-001`.
