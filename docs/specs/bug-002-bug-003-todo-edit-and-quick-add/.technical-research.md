## Story-Scoped File Map

### S01 – Persist Edited Due Dates
- `src/app/routes/todos.py:169-240` – `update_todo(...)` owns title/note/priority validation plus the current due-date parsing bug. The route currently calls `datetime.strptime(due_date, "%Y-%m-%dT%H:%M")`, which mismatches the UI's date-only input.
- `src/app/templates/app.html:121-149` – edit dialog declares `name="due_date"` on an `sl-input` with `type="date"`, so the supported browser-submitted format is date-only, not datetime-local.
- `src/app/templates/partials/todo_item.html:1-40` – todo row carries `data-todo-due-date="{{ format_date_input(todo.due_date) }}"` and the inline edit action passes the same formatted value back into the dialog.
- `src/app/static/js/app.js:111-124` – `openEditTodoDialog(...)` copies the row's `dueDate` data attribute into `#edit-todo-due-date`, so persisted state must already be in the format that the Shoelace date input accepts.
- `tests/test_todos.py:44-62` – existing update coverage already exercises due date persistence at a coarse level; this is the natural home for regression cases around reopen-state and clear-date behavior.

### S02 – Apply Default Priority on Quick Add
- `src/app/routes/todos.py:73-132` – `create_todo(...)` validates title, assigns `position`, creates the record, and returns the OOB partial. The constructor currently omits `priority`, so the stored value depends on external defaults that are not present here.
- `src/app/database.py:73-84` – `Todo.priority` is nullable and has no database default, so application code must set `low` explicitly for quick-add-created records.
- `src/app/templates/partials/todo_item.html:1-32` – row classes, data attributes, and the priority badge all reflect the stored `todo.priority`; a missing stored value leaks directly into the rendered UI and edit-dialog preload state.
- `src/app/templates/app.html:142-148` – the edit dialog priority selector defaults to `value="low"` only at initial render; reopen behavior still depends on the stored row data supplied to JavaScript.
- `tests/test_todos.py:13-30` – `test_create_todo` already expects `created.priority == "low"`, making this file both the current signal for the defect and the right place for stronger regression assertions.

## Shared Architectural Decisions
1. **Keep the HTML partial contract unchanged**
   - Both defects are in existing HTMX flows. The fix path stays inside the current FastAPI route handlers and fragment templates; no JSON endpoints, no client-side state rewrite, no changed OOB response pattern.
2. **Use route-level normalization where the bug currently lives**
   - The project intentionally validates todo inputs in route handlers, not through the Pydantic models under `src/app/models/`. Both specs should follow the existing handler-level pattern rather than introducing a new validation layer during defect triage.
3. **Treat the edit dialog's current control format as authoritative**
   - The edit dialog uses `type="date"` and the row/template helpers round-trip a date-only value. S01 should align the update route to that format and preserve the established blank-field-clears-date behavior.
4. **Treat explicit `low` assignment as the quick-add source of truth**
   - Because `Todo.priority` has no DB default, S02 should set the persisted value in `create_todo(...)` rather than relying on template defaults or later edit-dialog state.
5. **Preserve merge isolation despite shared modules**
   - The PRD explicitly requires BUG-002 and BUG-003 to remain two thin, independently landable stories. The specs should therefore call out non-overlapping hunk ownership inside `src/app/routes/todos.py` and `tests/test_todos.py` rather than collapsing the stories into one larger slice.
