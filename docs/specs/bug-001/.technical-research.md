# Technical Research - BUG-001

## Architecture Analysis

- The todo routes are HTML-first FastAPI handlers. `create_todo` and `toggle_todo` already compute the incomplete count with `_get_list_todo_count()` and return server-rendered partials with `hx-swap-oob` markers instead of JSON responses.
- `delete_todo` is the outlier. It verifies ownership and deletes the row, but returns a bare `Response(status_code=200)`, so HTMX removes the targeted row without receiving the sidebar count update payload.
- The repository already contains a dedicated delete OOB partial at `src/app/templates/partials/todo_deleted_oob.html`, which suggests the intended solution was to reuse the same OOB count pattern for deletes but the route was never wired to it.

## Relevant Source Patterns

- `src/app/routes/todos.py:33-37` - `_get_list_todo_count()` counts incomplete todos for one `TodoList`.
- `src/app/routes/todos.py:243-283` - `toggle_todo()` shows the canonical OOB pattern: mutate, commit, recompute count, then return `partials/todo_item_with_oob.html`.
- `src/app/routes/todos.py:286-306` - `delete_todo()` currently deletes and returns only `200`, which causes the stale sidebar badge defect.
- `src/app/templates/partials/todo_item_with_oob.html:1-4` - existing response shape combining the primary todo partial with an OOB `<span id="list-{{ list.id }}-count" hx-swap-oob="true">`.
- `src/app/templates/partials/todo_deleted_oob.html:1-2` - existing delete-specific OOB fragment containing only the sidebar count span.
- `tests/test_todos.py:84-92` - current delete coverage proves persistence only; it does not assert the returned HTML payload.
- `tests/test_integration.py:179-194` - existing integration coverage already asserts `toggle_todo()` emits an OOB swap, which is the closest behavioral test pattern to mirror.

## Implementation Notes for Executor

- Keep the delete flow HTMX-first: return an HTML partial, not JSON and not client-side JS.
- Capture `todo.list_id` before deletion so the count can be recomputed after `db.delete(todo)` and `db.commit()`.
- Preserve current non-happy-path behavior unless the spec says otherwise: nonexistent todo still returns `404`, unauthorized delete still returns `403`.
- The most direct proof is a route test that asserts both `hx-swap-oob` and the exact `id="list-{list_id}-count"` container, plus a count value that changes only when an incomplete todo is deleted.
