# Technical Research – BUG-001

## Codebase Pattern Inventory

- `src/app/routes/todos.py:33-37` defines `_get_list_todo_count(db, list_id)`, the existing incomplete-only count helper used by create and toggle.
- `src/app/routes/todos.py:125-132` and `src/app/routes/todos.py:276-283` show the established success pattern: mutate state, compute `count`, then return a `TemplateResponse` that includes an OOB count update.
- `src/app/routes/todos.py:286-306` is the defect site. It verifies ownership, deletes the row, commits, then returns an empty `Response(status_code=200)`, so HTMX has no OOB markup to apply.
- `src/app/templates/partials/todo_item_with_oob.html:1-4` proves the response contract used by create/toggle: main fragment plus `<span ... hx-swap-oob="true">`.
- `src/app/templates/partials/todo_deleted_oob.html:1-2` already exists for delete and targets the same DOM id, which makes this defect a missing-wiring issue rather than a missing-template issue.
- `src/app/templates/partials/todo_list_item.html:20` defines the sidebar badge target as `id="list-{{ list.id }}-count"`. The delete response must preserve that exact id.

## Behavioral Interpretation

- The sidebar count represents incomplete todos only. That is enforced in both `_get_list_todo_count(...)` and the template expression in `todo_list_item.html`.
- Deleting an incomplete todo should decrement the count after commit.
- Deleting a completed todo should still emit the OOB count refresh, but the value should be unchanged.

## Test Coverage Gaps

- `tests/test_todos.py:84-92` verifies only that delete returns `200` and removes the row from the database. It does not assert any response-body contract.
- `tests/test_integration.py:163-179` already contains a narrow OOB assertion for toggle (`hx-swap-oob` present). Delete needs comparable coverage, but with stricter assertions around the target id and count value.
- No existing test proves the completed-vs-incomplete delete distinction for sidebar count updates.

## Implementation Shape

- Preferred change surface is minimal: update only the delete success path and the relevant tests.
- No schema, routing, or JavaScript changes are required if the existing HTMX delete trigger already removes the row client-side and only needs the sidebar badge update from the server.
- In `AUTO_MODE`, the conservative assumption is that the current delete UI is already HTMX-driven and that a delete-specific OOB partial is sufficient to close the defect.
