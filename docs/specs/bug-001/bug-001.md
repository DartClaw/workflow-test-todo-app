# BUG-001 – Sidebar Incomplete Count Updates On Todo Delete

## Feature Overview and Goal
Fix the `BUG-001` regression where deleting a `Todo` removes the row but leaves the sidebar incomplete-count stale until a full page reload. The delete flow must follow the existing HTMX OOB swap pattern already used by todo create and toggle so the UI stays server-driven and consistent.

> **Technical Research**: [.technical-research.md](./.technical-research.md) _(codebase patterns, architecture analysis, test gaps)_

> - **Out-of-Band (OOB) swaps** are a core idiom. When one action needs to update multiple regions, the route returns a composite partial like `partials/todo_item_with_oob.html` that embeds `hx-swap-oob` markers. Example: toggling a todo updates both the todo row and the sidebar's incomplete-count badge in a single response. Before adding a new interaction, check whether it needs an OOB swap.

## Scenarios

### Delete Incomplete Todo Updates Sidebar Count
- **Given** a `TodoList` sidebar badge showing `1` incomplete `Todo`
- **When** the user deletes that incomplete `Todo` through the existing HTMX delete flow
- **Then** the response includes an OOB swap targeting `list-{list_id}-count` with value `0`, and the deleted `Todo` no longer exists in storage

### Delete Completed Todo Leaves Count Stable
- **Given** a `TodoList` with one incomplete `Todo` and one completed `Todo`
- **When** the user deletes the completed `Todo`
- **Then** the response still includes an OOB swap targeting `list-{list_id}-count`, and the count remains `1`

### Delete Rejects Unauthorized Access
- **Given** a `Todo` that belongs to another `User`
- **When** a different authenticated `User` sends the delete request
- **Then** the route returns `403` and does not change the sidebar count contract for the owner’s list

### Delete Missing Todo Returns Existing Error Contract
- **Given** a `todo_id` that does not exist
- **When** the client sends the delete request
- **Then** the route returns `404` and no delete side effects occur

## Scope & Boundaries

### In Scope
- Make the delete route return the same server-driven sidebar-count refresh pattern already used by create and toggle.
- Reuse the existing incomplete-count query helper and the existing delete-specific OOB partial.
- Add route-level test coverage that proves both the delete side effect and the OOB count update contract.

### What We're NOT Doing
- Refactoring todo delete into a broader response abstraction – this is a single-defect fix and existing helpers/partials already cover the need.
- Changing how completed todos are counted – the sidebar contract remains incomplete todos only.
- Changing client-side delete wiring or introducing custom JavaScript – the existing HTMX interaction stays in place unless implementation proves the server response alone is insufficient.
- Changing auth/session behavior – plain-text passwords and in-memory sessions are deliberate project constraints.

### Agent Decision Authority
- **Autonomous**: Reuse the existing helper and partial names if they already satisfy the delete response contract.
- **Escalate**: Only if the current delete trigger is not HTMX-driven and the defect cannot be fixed with a server-rendered partial alone.

## Architecture Decision

**We will**: keep delete in `src/app/routes/todos.py` and return the existing `partials/todo_deleted_oob.html` with a freshly computed incomplete count after the database commit – matching the project’s established OOB-swap pattern used by create and toggle, without introducing new client-side state handling.

## Technical Overview

### UI/UX Design
The visible change is limited to the sidebar badge for the active `TodoList`: it must refresh immediately after delete, regardless of whether the deleted `Todo` was incomplete or completed.

### Data Models
No schema changes. The count remains derived from `Todo.is_completed == False` within one `TodoList`.

### Integration Points
The delete route integrates with the existing sidebar badge DOM contract (`list-{list_id}-count`) and the existing HTMX OOB swap mechanism.

## Constraints & Gotchas
- **Constraint**: The app is HTMX-first and expects HTML fragments, not JSON – Workaround: return a partial response for delete rather than an empty `Response`.
- **Avoid**: Recomputing the sidebar count before the delete commit – Instead: delete, commit, then query the new incomplete count.
- **Critical**: The sidebar badge id is already consumed by OOB updates – Must handle by: preserving the exact `list-{list_id}-count` target.
